# 인수인계 문서

2026-11-01 기준으로, 로컬 Claude Code 세션에서 한 작업을 웹(claude.ai/code)에서 이어가기 위해 정리했다.

## 프로젝트 목표

왈라 설문 응답자가 현재 위치, 선택 규칙, 오류 수정 방법, 제출 결과를 화면만 보고 이해하며 끝까지 응답하게 만든다.
개선 대상은 네 가지다.

| 기능 | 개선 내용 |
|---|---|
| 오류 안내 | 문항 바로 아래에 원인과 고치는 법을 보여 주고, 정상 답은 유지한다 |
| 단일/복수 선택 구분 | 누르기 전에 몇 개를 고를 수 있는지 알 수 있게 한다 |
| 제출 상태·엔딩 | 처리 중, 실패, 성공을 구분하고 제출 완료를 확신하게 한다 |
| 진행도 | 현재 위치와 표시가 바뀌는 단위를 알 수 있게 한다 |

PRD 원문은 팀 내부 자료여서 공개 저장소에 넣지 않았다. 필요하면 사용자에게 요청한다.

## 현재 사이트

- 첫 화면과 `/ab-test`로 들어오면 `/ab-test.html`로 이동한다.
- `/survey`는 이전 React 화면이다. 링크는 없지만 주소를 직접 입력하면 열린다.
- Mixpanel 코드는 `public/ab-test.html` 안에 직접 들어 있다. 이 파일의 Project Token은 브라우저에 공개되는 값이다.
- React 코드는 `NEXT_PUBLIC_MIXPANEL_TOKEN` 환경 변수를 쓴다. 로컬에서는 `.env.local`에 넣는다(`.env.local.example` 참고). Vercel 환경 변수 등록 여부는 확인하지 않았다.

## A/B 테스트 구성

- 참가자 한 명이 A안과 B안을 모두 응답한다. 순서는 시작할 때 무작위로 정한다.
- 설문은 실제 왈라 설문 https://walla.my/v/8EGKnYmA1JMTRwCDwOrh 내용이다. 2페이지 16문항이고 모두 필수다.
- A안은 현재 왈라와 똑같이, B안은 개선안으로 만든다. 색상은 같은 파란색 계열로 맞춰서 어느 쪽이 개선안인지 드러나지 않게 한다.
- 마지막에 어떤 버전이 더 쉬웠는지와 그 이유를 묻는다.

### 복수 선택 규칙

| 문항 | 규칙 | A안 | B안 |
|---|---|---|---|
| 3번 | 정확히 2개 | 개수 안내 없음 | "2개 선택" 표시 |
| 6번 | 정확히 3개 | 개수 안내 없음 | "3개 선택" 표시 |
| 7번 | 2~3개 | 개수 안내 없음 | "2~3개 선택" 표시 |
| 12번 | 2개 이상 | 개수 안내 없음 | "2개 이상 선택" 표시 |

### A안: 왈라 동작을 그대로 따른다

- 비어 있으면 "최소 1개 옵션을 선택해주세요."가 뜬다.
- 개수가 부족하면 "최소 선택 항목을 충족하지 않습니다."가 뜬다.
- 개수를 넘기면 선택은 되고 바로 "최대 선택 항목을 초과했습니다."가 뜬다.
- 오른쪽 위에 "유효하지 않은 입력이 있습니다" 알림이 뜬다.
- 진행률은 1페이지 50%, 2페이지 100%이고, 2페이지에는 제목이 없다.

### B안: 개선 동작

- 최대 개수를 채우면 나머지 선택지가 잠긴다.
- 개수가 부족하면 "2~3개를 골라 주세요. 지금 1개 골랐어요."처럼 현재 개수를 알려 준다.

## Mixpanel

- 프로젝트: `codeint-mid-project` (id 4078821)
- 대시보드: [응답 화면 A/B 테스트 지표 (16문항)](https://mixpanel.com/project/4078821/app/boards#id=11621263)
- 무료 플랜이라 저장 리포트는 5개까지다. 새 대시보드를 만들 수 없어서 기존 리포트를 고쳐 쓰고 있다.
- 대시보드 전체에 `survey_version = cafe16` 필터가 걸려 있고, 기간은 2026-10-30부터다.

| 지표 | 보는 방법 |
|---|---|
| ① 설문 완료 시간 | `ab_response_submitted`의 `seconds` 중앙값 |
| ② 마지막 페이지 도달 대비 제출 완료율 | `ab_page_completed` 대비 `ab_response_submitted` 비율 |
| ③ 오류 수정 시간 | `ab_error_resolved`의 `seconds_to_fix` 중앙값 |
| ④ 선택 개수 오류를 본 응답 비율 | `ab_response_submitted`의 `count_rule_error` |
| ⑤ 선택 해제 횟수 | 3·6·7·12번 문항의 해제 횟수 |

### 지표를 다룰 때 주의할 점

- ②는 퍼널이 아니라 비율 계산식이다. 참가자가 두 버전을 모두 응답해서, 퍼널로 만들면 버전이 섞일 수 있다.
- 처음 만든 ④는 "1개만 고른 비율"이었다. 새 설문의 복수 선택은 모두 최소 2개라서 지표를 바꿨다.
- 전체 평균에는 두 번째 응답이 익숙해서 빨라지는 효과가 섞인다. 첫 응답끼리 비교하려면 `position = 1` 필터를 건다.
- 태그 추가 전에 들어온 16문항 응답 7건은 대시보드에 잡히지 않는다. 이미 받은 이벤트에는 속성을 나중에 붙일 수 없다.
- 5문항 시절의 결과는 대시보드 메모 카드에 남겨 두었다.
- 숫자는 참가자 수로 함께 읽는다. 표본이 적을 때는 참고용으로만 쓴다.
